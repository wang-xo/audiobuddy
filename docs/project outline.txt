Build a very small local Python CLI tool for summarizing audio files using the Google Gemini API.

Usage:

python summarize_audio.py /path/to/audio.m4a

Phase 1 Requirements:

1. Accept a local audio file path as a command-line argument.
2. Read GEMINI_API_KEY from the environment. Never hardcode credentials.
3. Upload the audio using the current Google GenAI Python SDK / Gemini Files API.
4. Send the uploaded audio to an appropriate current Gemini Flash model.
5. Ask Gemini to translate as necessary and produce in English:
   - date and time
   - detailed summary
   - discussion path, organized by topic
   - decisions
   - action items, including owner where identifiable (unidentified owners may be marked with the label "unknown")
   - open questions
6. Save the result as Markdown <original-name>-summary.md. The summary md should preserve a fixed heading structure according to point 5 above. If filenames conflict automatically create a numbered alternative.
7. Handle common errors clearly, including:
   - missing API key
   - nonexistent input file
   - unsupported file
   - Gemini API failure
8. Add requirements.txt and a short README with setup and usage instructions.
9. Keep the implementation simple, readable, and well commented.
10. Do not build a web UI, database, authentication system, or other infrastructure.

Before coding, inspect the current Google Gemini API documentation so you use the current SDK and model names rather than relying on old examples.

Notes:
- Assume the input audio files are mp3 format in this folder D:\Documents\Personal\audio\in
- Parse the filename for the date and time. If the audio filename is 2026-08-30 11_10_13.mp3 then the date is 30 August 2026 and the time is 11:10:13.
- Output md file should be in created/updated in this folder: D:\Documents\Personal\audio\out
- Accept timestamp-named MP3 and OGG files and warn if the file format is
  different than expected.
- CLI output should indicate success or failure with reason.

Silence trimming notes:

Before uploading the audio to Gemini, preprocess it locally using FFmpeg (or another relevant method).

Silence trimming requirements:

- Never modify or overwrite the original audio file.
- Silence trimming should run for any file with duration longer than 10 minutes
- Detect and remove long periods of silence.
- Be conservative: only remove silence lasting at least 30 seconds and -30dB.
- If no audio is trimmed, stop, and send the original audio file.
- Do not remove normal pauses between speakers.
- Preserve the audio format and quality as much as practical.
- Store the processed file as a temporary file.
- Report in the CLI and the markdown summary:
  - original duration
  - processed duration
  - amount of audio removed
  - percentage reduction
- Upload only the processed (trimmed) audio to Gemini.
- If FFmpeg is not installed, provide a clear error explaining how to install it.

Summary tracking requirements:

- Continue writing individual summary files using the current filename behavior.
- Also maintain one master Markdown file in D:\Documents\Personal\audio\out, named master-summary.md.
- The master file should contain one entry per source audio filename.
- If a file is summarized again, replace that source file's existing master entry rather than adding a duplicate.
- The individual retry output should still create a numbered alternative file as it does today.
- The master entry should point to the newest individual summary file for that source.
- Keep the master file sorted chronologically by the date/time parsed from the source filename.
- Use the cheapest safe master update strategy:
  - If the master file does not exist, create it.
  - If an entry for the same source filename already exists, replace that entry and rewrite the master file.
  - If the new entry timestamp is newer than or equal to the latest master entry timestamp, append it.
  - If the new entry timestamp is older than the latest master entry timestamp, insert it in chronological order and rewrite the master file.
- Consider a future optional --rebuild-master flag to rebuild or repair the master file from available individual summaries.
- Use stable hidden Markdown comments as entry markers so entries can be replaced reliably.
  Example:
  <!-- AUDIOBUDDY_ENTRY_START filename="2026-08-29 16_51_37.mp3" -->
  <!-- AUDIOBUDDY_ENTRY_END -->
- If Gemini or summary writing fails, do not update the master file.

Batch scan requirements:

- Add a --scan command that inspects only the top level of D:\Documents\Personal\audio\in. Do not recurse into subfolders.
- Preserve the existing single-file command for explicit processing or reprocessing of one file.
- Accept only MP3 or OGG files whose filenames use the existing
  YYYY-MM-DD HH_MM_SS filename convention.
- Report and skip unsupported files and invalid filenames; continue processing valid files.
- Read the master file once and treat a source filename already represented there as already processed.
- Process only new valid files, in chronological filename order.
- If no new valid files are found, print "No new audio files found." and exit successfully.
- Process batch files sequentially. If one file fails, report the failure, continue with later files, and exit nonzero after the batch if any file failed.
- Retry transient Gemini failures up to three additional times, with waits of 2, 4, and 8 seconds. Do not impose a delay after successful requests.
- Print final batch totals for processed, skipped, and failed files.
- Defer a --rescan command that deliberately reprocesses all files to Phase 2-4.
